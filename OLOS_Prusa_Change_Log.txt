OLOS Prusa Slicer Change Log
============================

Backend / Prusa Slicer
----------------------
- Added Prusa vector-based G-code generation from Prusa SL1 PNG masks.
- Added VisiCut-style output formatting:
  - Compact G0X...Y...S0 travel moves.
  - Powered moves like G1X...Y...S55F2000.
  - Modal contour continuation lines.
  - M3 / M5 layer blocks.
- Fixed feedrate after laser power so powered moves include feedrate, for example S55F2000.
- Fixed per-zone exposure so first, intermediate, and final layer power/speed settings apply.
- Fixed no-routine first layers so routine is skipped for the requested first layers.
- Forced Prusa supports, pads, and hollowing off in generated masks.
- Added Prusa-only infill angle.
- Added Prusa contour line count.
- Added Prusa infill lines per hatch.
- Kept physical hatch/contour line spacing fixed at 0.2 mm.
- Added multi-line contour generation using 0.2 mm spacing.
- Added multi-line hatch bundles using 0.2 mm spacing.
- Fixed hatch bundle spacing so lines are evenly spaced.
- Fixed incomplete corner hatch bundles being emitted with fewer lines than requested.
- Added adaptive fallback infill for thin regions where full bundles do not fit.
- Fixed hatch grid anchoring so complex/off-center models like Benchy do not get one-sided weaker infill.
- Fixed contour extraction resolution for cylinders and curved shapes.
- Changed contour extraction to keep full boundary points.
- Added small contour simplification to reduce pixel-stair jaggedness.
- Fixed layer count issues from Prusa supports, pads, and hollowing masks.
- Fixed Prusa preview/G-code layer Z interpretation for VisiCut-style repeated routine Z.
- Removed the temporary editable Line Spacing setting after deciding 0.2 mm should stay fixed.
- Added Prusa hatch rotation per layer, defaulting to 67 degrees, so each layer increments the hatch angle.
- Added contour/infill overlap control as a percent of the fixed 0.2 mm hatch spacing, defaulting to 15%.
- Added hatch scan order optimization with alternating/serpentine hatch direction between layers.
- Increased the Prusa contour line count limit to 25, allowing up to about 5 mm wall thickness at 0.2 mm spacing.

Frontend / Settings UI
----------------------
- Added Prusa UI controls for:
  - Infill Angle.
  - Hatch Rotation per Layer.
  - Infill Lines per Hatch.
  - Contour/Infill Overlap.
  - Optimize Hatch Scan Order.
  - Contour Line Count.
- Wired those fields through:
  - Frontend interfaces.
  - Constants/default settings.
  - Store/profile loading.
  - Backend Pydantic model.
  - Backend slicing dispatcher.
- Temporarily added Line Spacing, then removed it and restored fixed 0.2 mm.
- Increased the Prusa contour line count UI limit from 10 to 25.

Preview
-------
- Added support for commentless VisiCut-style G-code preview.
- Added logic to split infill and contour from M3 / M5 blocks.
- Added preview-only synthetic layer Z handling for VisiCut-style G-code.
- Fixed the skyscraper preview issue caused by routine Z being interpreted as real accumulated Z.
- Fixed layer slider behavior so it can move past the first layer.
- Fixed first-layer preview gap/offset.
- Fixed contour preview returning after it disappeared during earlier tests.
- Tried a solid translucent contour preview, then reverted it because it made infill/contour harder to separate.
- Removed noisy per-wall preview console logging.
- Added an estimate print time, which includes the total print time and the total recoating time.

Latest LPBF Feature Update - Detailed File Notes
================================================

Purpose
-------
This update added three LPBF-focused controls to the Prusa workflow:
- Inter-layer hatch rotation.
- Contour/infill overlap.
- Hatch scan order optimization.

It also fixed the contour line count limit so the UI and backend both support up to 25 contour lines, which equals about 5 mm wall thickness at the fixed 0.2 mm line spacing.

OLOS_Interface/src/components/3DSlicingTabComponent/components/MainToolsBar/components/components/PrintingConfigurations/components/PrusaSettings.vue
------------------------------------------------------------------------------------------------------------------------------------------------------
- Added a new Prusa input: Hatch Rotation per Layer.
  - Bound to prusaSettings.hatchRotationPerLayer.
  - Accepts values from 0 to 360 degrees.
  - Default value comes from constants.ts and is 67 degrees.
  - This controls how much the infill angle changes after each layer.
- Added a new Prusa input: Contour/Infill Overlap.
  - Bound to prusaSettings.contourInfillOverlap.
  - Accepts values from 0 to 100 percent.
  - Default value is 15 percent of the fixed 0.2 mm hatch spacing.
  - This lets the infill slightly overlap the innermost contour to reduce shell-core gaps.
- Added a new Prusa toggle: Optimize Hatch Scan Order.
  - Bound to prusaSettings.optimizeScanOrder.
  - Default is enabled.
  - Enables simple serpentine/alternating hatch direction.
- Increased the existing Contour Line Count input limit:
  - Old max: 10.
  - New max: 25.
  - Validation message was updated to match the new range.

  - hatchRotationPerLayer: number.

OLOS_Server/src/utils/threeD_printing_slice/src/prusa_slicer.py
---------------------------------------------------------------
- Applied inter-layer hatch rotation when generating each layer:
  - layer_angle = infill_angle + layer_index * hatch_rotation_per_layer.
  - The result is wrapped modulo 180 degrees because hatch lines at 0 and 180 degrees are geometrically equivalent.
- Applied contour/infill overlap by reducing the infill boundary clearance:
  - Base clearance comes from the number of contour lines and fixed 0.2 mm spacing.
  - The overlap amount is contour_infill_overlap times 0.2 mm.
  - Example default: 15 percent of 0.2 mm = 0.03 mm overlap.
- Added scan order optimization:
  - Hatch lines are ordered in a simple serpentine pattern.
  - Every other line reverses direction to reduce long laser jumps.
  - Every other layer reverses overall scan direction when optimize_scan_order is enabled.
- Increased backend line count normalization from 10 to 25:
  - This makes the new UI max actually produce up to 25 contour lines.
  - Without this backend change, the UI could accept 25 but the slicer would still silently clamp it to 10.
- Passed spacing, contour count, overlap, rotation, and scan order settings through the vector infill generator.

Prusa Metal Printing Settings Update - 2026-06-02
=================================================

Purpose
-------
- Added Prusa-only controls for metal printing tuning requested after Benchy preflight checks.
- Focused on heat/infill density and OLSK routine control while preserving the proven VisiCut-style G-code format.
- Kept the fixed intra-bundle line spacing behavior at 0.2 mm, but added a separate hatch bundle spacing control so infill density can be changed safely.

OLOS_Interface/src/components/3DSlicingTabComponent/components/MainToolsBar/components/components/PrintingConfigurations/components/PrusaSettings.vue
------------------------------------------------------------------------------------------------------------------------------------------------------
- Fixed the Contour/Wall Speed input suffix from "mm" to "mm/min" because the value is used as a G-code feedrate.
- Updated the Contour/Infill Overlap input to accept negative values from -100% to 100%.
  - Positive values push infill toward/into the innermost contour.
  - Zero keeps the neutral boundary behavior.
  - Negative values increase the gap between contour and infill when separation is needed for heat control or testing.
- Added an Infill Hatch Spacing input in millimeters.
  - This controls the distance between hatch bundles.
  - It does not change the fixed 0.2 mm spacing between the lines inside each multi-line hatch bundle.
  - Increasing this value reduces infill density and heat input.
  - Decreasing this value increases infill density, with backend protection so it cannot become smaller than the bundle width.
- Added a Reservoir Lift per Layer input in millimeters under Machine Routine.
  - The UI value is entered as a positive distance, for example 0.3 mm.
  - The backend converts it to the current machine convention by outputting a negative A-axis move, for example G1 A-0.3 F50.

OLOS_Server/src/utils/threeD_printing_slice/src/prusa_slicer.py
---------------------------------------------------------------
- Added support for signed contour_infill_overlap values.
  - Previous behavior clamped overlap to 0..1.
  - New behavior allows -1..1, so negative overlap increases boundary clearance and creates a gap between infill and contour.
- Added infill_hatch_spacing support in the vector infill generator.
  - The hatch spacing setting controls pitch between hatch bundles.
  - The fixed 0.2 mm intra-bundle spacing is still used for the individual parallel lines inside each hatch/contour group.
  - If hatch spacing is set too low, pitch is clamped to at least the width required by the selected hatch line count.
- Preserved existing VisiCut-style powered move formatting such as S55F2000.
- Preserved the existing OLSK routine block structure.
